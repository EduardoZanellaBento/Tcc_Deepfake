### Passo 2 — Aplicar o bloco `espectrograma:` no `config.yaml`

Remova o bloco de comentário «BLOCO CONGELADO» inteiro e substitua o bloco
`espectrograma:` por este — que é o **aprovado, verbatim**, mais o sub-bloco de
defaults exigido:

```yaml
# =============================================================================
# ENTRADA DA CNN — DEFINIÇÃO FECHADA EM 17/09/2026
# As sete decisões (P1–P7) foram respondidas e aprovadas pelo orientador. O
# registro, com a evidência que motivou cada uma, está em
# results/metricas/DECISOES_PENDENTES_CNN.md (v5). NENHUMA SE REABRE.
#
# A partir de 21/09 (B4.2) esta definição fica CONGELADA no mesmo sentido que as
# features: regenerar os 74.453 tensores só por erro grave, com decisão
# registrada. A assinatura vigente é gravada em
# data/espectrogramas/espectrogramas.meta.json, conferida pela guarda de
# retomada do gerador — o mesmo mecanismo do features.meta.json.
#
# POR QUE n_fft = 1024 COM win_length = 400 (formulação correta, exigida):
#   a janela de análise continua em 400 amostras (~25 ms), logo a resolução
#   física determinada pela janela NÃO muda e nenhuma informação nova é criada.
#   A FFT de 1024 aumenta a DENSIDADE DE AMOSTRAGEM DA DFT por zero-padding
#   (513 bins em vez de 257), o que permite representar o banco de 128 filtros
#   Mel de maneira numericamente mais adequada. Com n_fft=512, 61 dos 128
#   filtros leriam <= 2 bins e 12 pares compartilhariam o bin de pico — regime
#   degenerado sobre o qual o librosa NÃO emite aviso.
#
# POR QUE db_ref = 1.0 (e por que a outra justificativa está PROIBIDA):
#   NÃO é para "preservar o ganho original das gravações" — esse ganho já foi
#   removido a montante pela normalização de pico por áudio, antes do VAD
#   (src/data/preprocessamento.py -> normalizar_amplitude). A razão real é
#   dupla: (a) não introduzir uma SEGUNDA normalização, relativa ao máximo do
#   próprio espectrograma, que contradiria a normalização global da P3; e
#   (b) manter paridade com a não-linearidade que librosa.feature.mfcc já
#   aplica, que usa os defaults do power_to_db.
#
# RESSALVA DO top_db = 80 (documentar no texto): o piso fica limitado a 80 dB
#   abaixo do máximo DAQUELE EXEMPLO. A região de padding vira, por isso, um
#   platô constante DENTRO de cada exemplo, com valor (max - 80) que VARIA entre
#   exemplos. Não invalida a decisão; precisa estar escrito.
# =============================================================================
espectrograma:
  tipo: "mel"
  sample_rate: 16000
  n_fft: 1024
  win_length: 400
  hop_length: 256

  n_mels: 128
  fmin: 0
  fmax: 8000

  power: 2.0
  escala: "db"
  db_ref: 1.0
  top_db: 80

  center: true

  altura: 128
  largura: 251

  normalizacao: "global_por_mel"
  mascarar_agregacao: true

  # Defaults do librosa 0.11 que são metodologicamente relevantes e que o
  # orientador exigiu registrar explicitamente. NÃO são decisões novas: são os
  # valores que o código já usaria por omissão, fixados aqui para que uma
  # atualização de biblioteca não os mude em silêncio. O gerador do B4.1 deve
  # PASSÁ-LOS EXPLICITAMENTE ao librosa, não confiar no default.
  #
  # `mel_norm` e `htk` importam para a PARIDADE com o ramo clássico:
  # librosa.feature.mfcc usa norm='slaney' e htk=False na filterbank Mel, logo
  # o espectrograma da CNN precisa usar os mesmos para que a convenção de
  # escala Mel e as frequências centrais dos 128 filtros sejam as mesmas.
  # (A densidade de amostragem da DFT difere, por causa do n_fft — ver acima;
  # é a convenção da escala que é comum aos dois ramos, não o nº de bins.)
  defaults_librosa_registrados:
    window: "hann"
    pad_mode: "constant"
    htk: false
    mel_norm: "slaney"
    amin: 1.0e-10
```

**Conferências antes de commitar:**

- `yaml.safe_load` abre o arquivo sem erro:
  `python -c "from src.utils.config import carregar_config; from pathlib import Path; c=carregar_config(Path('.')); print(c['espectrograma'])"`
- `amin` sai como **float** `1e-10`, não como a string `"1.0e-10"`. Em YAML,
  `1.0e-10` é float; `1e-10` **também** é aceito pelo safe_load do PyYAML, mas
  `1.e-10` não. Se o print mostrar `str`, corrija a notação.
- O bloco `features:` **não é tocado**. Ele continua com `n_fft: 512` e é assim que

### Passo 3 — Nota de limitação no `config.yaml` (5 minutos, e evita uma pergunta ruim na banca)

Aplique o teste da regra de escopo a um fato que decorre das decisões e que a banca
pode achar sozinha:

> **Pergunta provável:** «se `n_fft=512` com `n_mels=128` é um regime degenerado, o
> MFCC do ramo clássico não sofre do mesmo problema? Ele usa 512.»

`librosa.feature.mfcc` monta o Mel internamente e, com os parâmetros congelados
(`n_fft=512`) e o `n_mels` default da biblioteca, **cai no mesmo regime**.

**Aplicando a regra de escopo: isso NÃO impede a validade do experimento
principal.** Duas razões, e as duas são defensáveis por escrito:

1. o MFCC aplica uma **DCT** sobre as 128 faixas e retém apenas **20** coeficientes —
   o detalhe fino que a filterbank degenerada representaria mal é, em boa parte,
   descartado nessa compressão;
2. o que a comparação exige é que os **dois ramos partam do mesmo áudio
   pré-processado** — e partem, por construção (`preprocessar_audio` é o mesmo). A
   diferença de representação é justamente o **objeto de estudo**, não um confundidor.

**Portanto: vai como LIMITAÇÃO, não como experimento.** Acrescente ao comentário do
bloco `features:` (sem mexer nos valores) e ao rascunho de limitações do B6:

```yaml
  # LIMITAÇÃO REGISTRADA [B4.0, 18/09/2026] — a filterbank Mel interna do
  # librosa.feature.mfcc, com o n_fft=512 congelado, cai no mesmo regime
  # degenerado que motivou a P4 a adotar n_fft=1024 na CNN. NÃO foi corrigido, e
  # deliberadamente: as features estão congeladas desde 30/08 e re-extrair
  # abriria o Bloco 2 dentro do cronograma de recuperação. O impacto é atenuado
  # pela DCT do MFCC, que retém só 20 dos 128 coeficientes. Registrado como
  # limitação no TC II (não como experimento) pela regra de escopo de 17/09.
```

**Confira antes de escrever isso como fato.** No B4.1, quando o piloto estiver
rodando, gaste 5 minutos:

```python
import librosa, numpy as np
# filterbank efetivamente usada pelo ramo clássico (parâmetros congelados)
M = librosa.filters.mel(sr=16000, n_fft=512, n_mels=128, fmin=0, fmax=8000,
                        htk=False, norm="slaney")
print("filtros com <= 2 bins ativos:", int(((M > 0).sum(axis=1) <= 2).sum()))
print("pares com o mesmo bin de pico:",
      len(np.argmax(M, axis=1)) - len(set(np.argmax(M, axis=1).tolist())))
```

Se o número não bater com os 61 filtros citados na P4, **ajuste a redação da
limitação ao número medido** — nunca o contrário.
